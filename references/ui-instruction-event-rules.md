# UI 指令与事件规则

## 核心区别

- 指令: 用于界面内部通信。一个控件发出指令，其他控件通过自定义属性接收并响应，整个过程在客户端完成。
- 事件: 用于界面通知创意代码或组件自定义能力。只有当后续需要代码执行玩法逻辑时，才把指令转成事件。

## 优先级

纯界面表现优先使用指令，不进入创意代码。

适合用指令的情况:

- 关闭当前面板
- 打开另一个面板
- 显示或隐藏某个控件
- 显示指定外框图
- 播放 UI 动画
- 改透明度、位置、缩放
- 把一个指令转发成另一个指令

适合用事件的情况:

- 传送玩家
- 修改创意代码变量
- 发奖励或扣物品
- 创建、销毁、移动组件
- 改天气、时间、滤镜等玩法状态
- 触发组件自定义能力里的逻辑

## 控件自定义属性

一个控件可以添加多个自定义属性。按钮点击发出一个指令后，可以让多个控件分别响应该指令，也可以让某个控件通过 `发送指令` 继续转发后续指令。

示例:

```text
框钮一
- 点击发出界面指令: 选框一
- 自定义属性: 收到 选框一 后发送指令 关闭选框板
- 自定义属性: 收到 选框一 后发送指令 入拍照
- 自定义属性: 收到 选框一 后发送指令 显框一
```

接收控件:

```text
选框板
- 收到 关闭选框板 后隐藏

拍照板
- 收到 入拍照 后显示

框一
- 收到 显框一 后显示
```

如果只是上述 UI 联动，不需要 `发送事件`，也不需要创意代码里的 `收到事件`。
